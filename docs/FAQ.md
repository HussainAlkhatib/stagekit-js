# FAQ

## What is StageKit, in one sentence?

A library of 980 small, pure string transformations that you snap together
into a pipeline.

## Why are stages numbered instead of named?

Every stage has **two** identifiers: a unique `id` (`mod-0042`) and a unique
human-readable `name` (`Caesar shift +1`). In this catalog both are unique -
no two stages share a name - so you can address a stage either way. The `id`
is the stable key: it never changes and never gets reused, which makes it
safe to store in configs and scripts. The `name` is meant for people and may
be reworded between releases, so prefer the id when you need a guarantee.

## Do I have to memorise ids?

No. Use `registry.search(...)`, `registry.findByPrefix(...)`. Ids are only needed when you want to pin an
exact stage in code or documentation.

## What id do I give a new stage?

Use `registry.nextId()`. It returns the first free id after the current
size, e.g. `mod-0982`. The format is always `mod-` plus four digits.

## Why does the demo `pipeline` produce garbage?

Because it runs **all** 980 stages in id order, and later stages are not
meant to follow earlier ones. It exists as a smoke test. Real code builds an
explicit pipeline with `createPipeline`.

## Can a stage have side effects?

It can, but it must not. Stages are expected to be pure: same input, same
output, no mutation, no I/O. Purity is what makes them safe to reorder and
reuse.

## Are stages mutable?

No. `defineStage` calls `Object.freeze`, so the exported object cannot be
changed.

## What happens if I register two stages with the same id?

`createRegistry` throws a `StageError` with `duplicate stage id`.

## What is the difference between `name` and `id`?

| | `id` | `name` |
| --- | --- | --- |
| Format | `mod-0042` | `Base64 encode` |
| Unique | Always | Always |
| Audience | Machines | People |
| Stable | Yes, never reused | May be reworded |

## How do I reorder a pipeline?

Stages are just values. Build the array in whatever order you want:

```js
createPipeline([c, a, b]);
```

## Can I stop a pipeline early?

Yes: `pipe(value, { limit: 3 })` runs only the first three stages.

## How is the catalog kept in sync?

Everything under `src/modules/` and `docs/CATALOG.md` is generated by
`scripts/generate.js`. Run `npm run generate` after changing the generator.
`npm run lint` verifies structure and `npm test` verifies behaviour.
